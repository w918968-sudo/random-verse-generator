# 扩展边界

判断「改起来多贵」的分档。动工任何新功能前先对号入座。

## 🟢 天然支持（低成本，直接做）

当前架构为这些设计好了扩展点：

| 需求 | 怎么改 | 涉及文件 |
| --- | --- | --- |
| 增加经文 | 在 `VERSE_SELECTIONS` 加条目 → `data:build` + `data:validate` | `scripts/verse-selections.mjs` |
| 增加主题 | `THEMES` 加一项，并确保该主题 ≥8 条经文 | `verse-selections.mjs`（`en.mjs` 的 `THEMES` 同步） |
| 改文案 | 集中改字符串 | `src/i18n/en.mjs` |
| 改配色/样式 | 改设计 token 或样式 | `src/styles/global.css` |
| 加静态页面 | 新增 `.astro` 页面 + 手动补 sitemap | `src/pages/`、`public/sitemap.xml` |

## 🟡 需要改造（中成本，先设计）

| 需求 | 为什么不是现成的 | 建议做法 |
| --- | --- | --- |
| 多语言界面 | UI 字符串已集中，但经文固定英文 WEBP；需要语言切换机制 | 新增 `i18n/zh.mjs` + 语言选择，见 B-12 |
| 多译本 | 数据管线硬编码 `translationId: 'WEBP'`，且每个译本有独立源与许可证 | 扩展管线支持多源 + 许可证审查，见 B-17 |
| 本地持久化（收藏） | 无存储层，属「加功能」而非改架构 | `localStorage`，见 B-15 |
| 分享带主题参数 | 需解析 URL query 预选主题 | 见 B-05 |
| 自动化测试/CI | 现无测试基建 | 见 [testing.md](testing.md)、B-07/B-08 |

## 🔴 超出边界（需重新架构，或明确不做）

| 需求 | 为什么超出 | 触发条件 |
| --- | --- | --- |
| 用户账户 / 登录 | 纯静态、无后端、隐私承诺 | 只有明确要「跨设备同步收藏」才立项 |
| 云端收藏 / 服务端随机 | 需要后端与存储 | 同上 |
| 全本圣经搜索 / 全文浏览 | 需打包 66 卷（体积）或后端索引 | 见 B-16，先定数据策略 |
| 用户生成内容 / 评论 | 需后端 + 审核 | 明确不做 |

## 边界红线（改之前必须重看）

1. **经文文本不得手打** —— 必须来自官方源、构建时提取、`validate` 通过。
2. **隐私承诺优先** —— 任何分析/上报不得收集经文文本、具体引用；主题类别若要上报必须同步改隐私页（见 R-01）。
3. **保持纯静态** —— 引入任何服务端前，先论证是否值得放弃零运维 / 零成本 / 隐私友好的现状。
